# One bounded implementation outcome

Use this template only for a real implementation contract. Remove instructions
and irrelevant sections; never mark ready because headings are present.
Lifecycle rules are in [WORKFLOW](../docs/development/WORKFLOW.md).

## Intent

State what should become possible, why, and the externally observable success.

## Required context

Link only the authority and existing files needed for this slice. Mark research
as non-normative and identify any unresolved conflicts.

## Approach and tooling choice

State non-obvious choices and dependencies. Distinguish existing tools from
planned commands. Do not specify incidental internals without a reason.

## Invariants

State meanings, identities, permissions, behavior, and task acceptance that must
not change. Name the owner of any necessary contract revision.

## Non-goals

Exclude adjacent work likely to distract an implementer or change the experiment.

## Interfaces and observable behavior

Define applicable inputs, outputs, errors, bounds, and meaningful edge cases.

## File map

Identify existing and planned paths and their jobs; planned paths are not links
to nonexistent files.

## Implementation tasks

List the few independently understandable steps required for this outcome.

## Acceptance criteria

Use stable AC identifiers, observable conditions, and a verification mapping.
Expected answers must come from a specified source outside the candidate behavior.

## Verification plan

List commands, required environment, expected observations, and evidence to retain.
Mark unexecuted commands and unavailable checks explicitly.

## Readiness and history

Record the readiness review and unresolved dependencies. After development begins,
append baseline revision, decisions, failures, evidence, and review dispositions.
